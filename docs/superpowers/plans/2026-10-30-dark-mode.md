# Dark Mode for Windows Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a System / Light / Dark theme setting to Transmission Remote GUI on Windows, rendering the app dark via the MetaDarkStyle package.

**Architecture:** MetaDarkStyle is vendored as a Lazarus package under `metadarkstyle/` and required by `transgui.lpi`. `CheckAppParams` in `main.pas` reads `[Interface] Theme` from the ini before `Application.Initialize` and applies the dark style. The Options dialog exposes the setting (restart required). Custom drawing is audited in dark mode and fixed with system colors only.

**Tech Stack:** Lazarus 4.0 / FPC 3.2.2 (`C:\lazarus`), LCL win32 widgetset, MetaDarkStyle (upstream `zamtmn/metadarkstyle` commit `e38933a`).

**Spec:** `docs/superpowers/specs/2026-10-30-dark-mode-design.md`

## Global Constraints

- Windows only behavior; Linux/macOS builds must still compile and behave exactly as before.
- Windows 10 1809+ for dark rendering; older Windows stays light without errors.
- Setting: `[Interface] Theme` integer, 0 = System (default), 1 = Light, 2 = Dark; out-of-range → System.
- Theme changes apply after restart only; reuse existing `sRestartRequired` message.
- Light mode must be pixel-identical to upstream: when Theme = Light, do not call `ApplyMetaDarkStyle` at all.
- Drawing fixes use system colors or `GetLikeColor`-style adaptive math; never hard-coded dark RGB values.
- `metadarkstyle/` is third-party: no edits besides the vendoring itself.
- Follow `.editorconfig` (LF, 2-space indent for .pas/.lpi/.lfm), `{$mode objfpc}{$H+}`, English comments.
- Commit subjects: imperative, capitalized, no Conventional Commit prefix; end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- No generated artifacts committed (`*.exe`, `*.res`, `*.ppu`, `units/`, `lib/`, `*.bak`). Exception: `metadarkstyle/src/CustomDark.lrs` is source and must be committed.

## Review Focus

1. Corrupt or out-of-range `Theme` value in the ini (`7`, `-1`, `abc`) → app starts in System mode, Options shows "System".
2. Theme changed in Options, then dialog cancelled → nothing written, no restart prompt.
3. Theme and Language changed in one OK click → exactly one restart message, both values saved.
4. Disconnected state in Dark mode (grids/edits switched to `clBtnFace`) → still readable, visibly disabled.
5. Portable mode / `--home=<dir>` → Theme is read from and written to that same ini (shared `Ini` object).

Tests for each are placed in Task 3 (items 1, 5), Task 4 (items 2, 3), Task 5 (item 4).

```pascal
  ThemeLight  = 1;
  ThemeDark   = 2;
```

Next to the other interface function declarations (near `function CheckAppParams: boolean;`), add:

```pascal

```

In the implementation `uses` clause (line ~962), add a Windows block before `synacode`:

```pascal
{$ifdef windows}
  uDarkStyleParams, uDarkStyleSchemes, uMetaDarkStyle,
{$endif windows}
```

Immediately before `function CheckAppParams: boolean;`'s implementation, add:

```pascal
function ReadThemeSetting: integer;
begin
  Result:=Ini.ReadInteger('Interface', 'Theme', ThemeSystem);
  if (Result < ThemeSystem) or (Result > ThemeDark) then
    Result:=ThemeSystem;
end;

{$ifdef windows}
procedure ApplyTheme;
begin
  case ReadThemeSetting of
    ThemeLight:
      exit; // Keep the native light theme untouched
    ThemeDark:
      PreferredAppMode:=pamForceDark;
    else
      PreferredAppMode:=pamAllowDark; // Follow the Windows app theme
  end;
  ApplyMetaDarkStyle(DefaultDark);
end;
{$endif windows}
```

In `CheckAppParams`, directly after:

```pascal
  Ini:=TIniFileUtf8.Create(FHomeDir+ChangeFileExt(ExtractFileName(ParamStrUTF8(0)), '.ini'));
  Ini.CacheUpdates:=True;
```

add:

```pascal
{$ifdef windows}
  ApplyTheme;
{$endif windows}
```
